# GridFlow Reference Analytics

The control room is a Grand Prix egress planning surface using one explicitly
external reference source: Iowa DOT public camera `DQTV17`. It shows the
camera's live HLS stream and vehicle-only analytics generated by the separate
gateway. The reference camera is in Iowa, not at a Grand Prix venue, and the
interface intentionally provides no signage, stewarding, occupancy, capacity,
or other venue-control actions.

The map has two real geographic modes: the Autodromo Nazionale Monza planning
context and the Iowa camera location returned by the public source metadata.
No static queue map, risk nodes, demonstration still, or fixture data is used
in the production dashboard.

## Local run

```powershell
npm.cmd ci
npm.cmd run lint
npm.cmd run test
npm.cmd run build
npm.cmd run dev
```

The application is available at `http://localhost:3000`.

`/api/reference/source` fetches Iowa DOT metadata at request time.
`/api/reference/current` and `/api/reference/history` read signed gateway
observations from the Control API using the server-held read token.

## Required deployed configuration

```text
CONTROL_API_READ_TOKEN=<Control API controller read token>
```

In Cloudflare, the control room uses the `CONTROL_API` service binding. For
local Next.js development, set `CONTROL_API_URL` in `.env.local` as shown in
`.env.example`.

The legacy controller routes remain protected by Cloudflare Access for a
future authorised venue-source integration. There is no demo identity bypass.
